Get started

The Glossematics embeddings server exposes {{MODEL_ID}} through an OpenAI-compatible REST API. It runs on-device via Core ML and binds to the loopback interface only — requests never leave this machine, and no API key is required.

Base URL: {{BASE_URL}} — every endpoint below is relative to it. Send Content-Type: application/json.

SERVER PROPERTIES

PropertyValue
Model{{MODEL_ID}}
Matryoshka dimensions{{MATRYOSHKA}} (default {{DEFAULT_DIMENSIONS}})
Max input items{{MAX_BATCH}} per request
Max request body{{MAX_BODY_MB}} MiB
Semantic space{{SPACE_ID}}

PROBE THE SERVER

curl -s {{BASE_URL}}/health
curl -s {{BASE_URL}}/v1/models

Create embeddings

To create embeddings make a POST call to /v1/embeddings. The request body is JSON; vectors come back in input order as an all-or-nothing batch — a failure anywhere rejects the whole request.

QUERY PARAMETERS

FieldTypeDescription
modelStringRequired. Must be {{MODEL_ID}}.
inputString | ArrayRequired. One text string, or an array of strings. Empty strings and empty arrays are rejected.
dimensionsInteger(optional) Matryoshka truncation: one of {{MATRYOSHKA}}. Defaults to {{DEFAULT_DIMENSIONS}}. The server loads one model instance per requested size on first use.
encoding_formatString(optional) float (default) returns a JSON number array; base64 returns little-endian float32 bytes, base64-encoded.
taskString(optional) Retrieval conditioning: retrieval.query or query for queries; retrieval.passage, passage, or document for indexed text. Defaults to passage. See Roles & spaces.
roleString(optional) Alias for task using query / document.
image_pathString(optional, per input item) Absolute path to a local PNG/JPEG file to embed with the vision tower. Local extension — not part of the OpenAI schema.
audio_pathString(optional, per input item) Absolute path to a local WAV/PCM file (≤ 30 s at any rate; converted to 16 kHz mono). Local extension.

Mix text and media by passing objects as array items: {"text": "..."}, {"image_path": "/abs/x.png"}, {"audio_path": "/abs/x.wav"}, or {"path": "/abs/x", "kind": "image"|"audio"}.

RESPONSE

FieldDescription
objectAlways list.
data[]Objects of {object: "embedding", index, embedding}, ordered by input. embedding is a float array or a base64 string per encoding_format.
modelEcho of the served model id.
usage{prompt_tokens, total_tokens} — real tokenizer counts of the raw text input; media items contribute zero.
X-Glossematics-Space / -DimensionsResponse headers naming the semantic space and the vector size, for storage-side provenance checks.

REQUEST

curl -s {{BASE_URL}}/v1/embeddings \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "{{MODEL_ID}}",
    "input": ["How do I cool an overheating laptop?"],
    "task": "retrieval.query",
    "dimensions": 512
  }'

RESPONSE

{
  "object": "list",
  "data": [
    {
      "object": "embedding",
      "index": 0,
      "embedding": [0.018063795, 0.01642996, ...]
    }
  ],
  "model": "{{MODEL_ID}}",
  "usage": {"prompt_tokens": 9, "total_tokens": 9}
}

Roles & spaces

The model conditions every input with a retrieval role. Query-conditioned and document-conditioned vectors live in different semantic spaces: the response header X-Glossematics-Space changes when the role changes. Similarity is only meaningful between a query vector and document vectors from the matching space.

The default role is document/passage — the recipe for indexed corpus vectors, which is what an embeddings endpoint stores. For search-side requests, pass "task": "retrieval.query" explicitly.

INDEX THEN QUERY

# 1) index documents (default passage role)
curl -s {{BASE_URL}}/v1/embeddings -H 'Content-Type: application/json' \
  -d '{"model":"{{MODEL_ID}}","input":["Paris is the capital of France."]}'

# 2) embed the query with query conditioning
curl -s {{BASE_URL}}/v1/embeddings -H 'Content-Type: application/json' \
  -d '{"model":"{{MODEL_ID}}","input":["capital of France?"],"task":"retrieval.query"}'

List models

GET /v1/models returns the served model in OpenAI list form; /v1/models/{id} returns it as a single object.

RESPONSE

{
  "object": "list",
  "data": [
    {
      "id": "{{MODEL_ID}}",
      "object": "model",
      "created": 1790013228,
      "owned_by": "glossematics"
    }
  ]
}

Health

GET /health reports readiness. Polling it also warms the default dimension, so a first embedding request is not the first thing to pay model-load cost.

FieldDescription
statusok once the default dimension is loaded, loading during first load, error (HTTP 503) if the bundle failed validation.
loaded_dimensions / loading_dimensionsMatryoshka sizes with live model instances, and sizes currently loading on demand.
spaceSemantic space fingerprint of the loaded model.
model / default_dimensions / portStatic server identity.

RESPONSE

{
  "status": "ok",
  "model": "{{MODEL_ID}}",
  "default_dimensions": {{DEFAULT_DIMENSIONS}},
  "loaded_dimensions": [{{DEFAULT_DIMENSIONS}}],
  "loading_dimensions": [],
  "space": "glossematics:omni-small:sha256:2dd14268...",
  "port": {{PORT}}
}

Errors

Every failure returns an OpenAI-shaped envelope:

ERROR ENVELOPE

{
  "error": {
    "message": "dimensions must be one of [32, 64, 128, 256, 512, 1024] for this model",
    "type": "invalid_request_error",
    "param": "dimensions",
    "code": null
  }
}
StatusMeaning
400invalid_request_error — malformed JSON, missing model, empty input, unknown task, unsupported dimensions, text beyond the 32,768-token limit, or a missing/unreadable media path.
404model_not_found — the model id does not match the served model, or an unknown route.
405Method not allowed for the route (e.g. GET on /v1/embeddings).
413Request body exceeds the {{MAX_BODY_MB}} MiB limit.
431Request headers exceed the size limit.
500api_error — inference or model failure. Batch embedding is atomic: nothing was embedded.
503Health endpoint reporting a failed model load.
