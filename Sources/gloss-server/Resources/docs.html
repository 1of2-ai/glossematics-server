Create embeddings

curl {{BASE_URL}}/v1/embeddings \
  -H 'Content-Type: application/json' \
  -d '{"model":"{{MODEL_ID}}","input":["one","two"]}'

Text accepts a string, an array of strings, one token-ID array, or an array of token-ID arrays. The standard model, dimensions, encoding_format, and user fields are accepted; dimensions must be omitted or {{DIMENSIONS}} because this model has no Matryoshka truncation. Unknown fields are rejected. Each input may use up to {{MAX_TOKENS}} tokens including the chat template, and a request up to {{MAX_REQUEST_TOKENS}} tokens across all inputs. encoding_format supports float or little-endian float32 base64.

Queries and documents share one encoding. BidirLM has no query/document prefixes: every text is wrapped in the model's user-turn chat template and mean-pooled over all tokens, matching the upstream Sentence Transformers recipe. Token-ID inputs are wrapped in the same template. Responses carry X-Glossematics-Space, X-Glossematics-Dimensions, and X-Glossematics-Compute.

Short inputs from concurrent requests are packed into shared executions (up to 64 sequences and 512 tokens) without padding each one. Longer documents run in 512-token chunks and yield the accelerator between chunk operations, so a long document does not block short queries.

Compute modes

modeCore ML unitsbehavior
anecpuAndNeuralEngineDefault. Startup verifies that every operation of every function is placed on the Neural Engine and refuses to become ready otherwise, so work never falls back to the CPU silently.
gpucpuAndGPUSame bundle and numerics on the GPU; placement is reported in /health.
cpucpuOnlySame bundle on the CPU, text only: the media towers are not qualified on the CPU backend, so media inputs are rejected with unsupported_modality. Correct but slow for long documents.

The mode is chosen once with --compute. The server never switches between modes at runtime. This process runs {{COMPUTE}}.

Media and messages

Loaded modalities: {{MODALITIES}}. OpenAI does not define media input for embeddings, so Glossematics accepts explicit content objects with base64 data URLs. Each item returns one vector in the same space as text:

{"model":"{{MODEL_ID}}","input":[
  {"type":"input_image","image_url":"data:image/png;base64,iVBOR..."},
  {"type":"input_audio","audio_url":"data:audio/wav;base64,UklGR..."},
  {"type":"message","content":[
    {"type":"input_text","text":"a spectrogram of"},
    {"type":"input_audio","audio_url":"data:audio/wav;base64,UklGR..."}]}]}

A message is one user turn interleaving text, images, and audio; it produces a single embedding. Images accept PNG, JPEG, and WEBP up to 20 MiB; audio accepts WAV up to 20 MiB. Video is not supported and is rejected with unsupported_modality, as are modalities the loaded bundle does not include. Remote URLs and local paths are never fetched.
